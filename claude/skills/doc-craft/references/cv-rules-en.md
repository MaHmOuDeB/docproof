# English CV Rules

The fact base and the base CV are the sources of truth. Tailored versions are derived from them:
trim and reorder, never let a tailored version drift into new claims.

## Bullet standard

Every bullet clears the "the work got better because I was there" bar: impact, not task
completion. If a bullet only describes the activity and not what changed, add the outcome or cut
the bullet.

## Impact without disclosing confidential numbers

Employer data (revenue, conversion, user counts) is often confidential. Substitutes that stay
honest:
- **Adoption or shipped outcomes**: "used by 5 teams", "30+ of 40+ tests shipped"
- **The candidate's own efficiency metrics**: time saved by their own tool or process
  ("~6 hours to ~45 minutes") is about their work, not company revenue
- **Scope as a proxy**: number of tests, teams, markets, users served
- **Directional language** ("significantly reduced") when a real number exists but can't be
  disclosed; never as a cover for a number that doesn't exist

## Format

- Reverse chronological.
- Length: a comprehensive base CV (~2 pages); tailored versions ~1–1.5 pages. Relevant evidence
  beats page count; don't cut it just to reach one page.
- Per role: title, company, location, dates.
- Bullets, not paragraphs. Lead with a strong verb.
- Dates with month names (`Mar 2022 – Aug 2025`): unambiguous internationally.
- The Skills section is a defensible list: nothing the candidate can't speak to in an interview.

## Standing constraints live in the fact base

Every candidate has a few wording rules that come up in every application: how to state tenure
("nearly three years", never "3+" if it's 2 years 10 months), the ceiling on a skill ("SQL: no
'advanced'"), a tool that must always be named together with another, a language level that
must never be rounded up. Record them in the fact base (`## Experience` safe-wording notes,
`## Skills` depth, `## Known gaps`) so every run and `docproof verify` applies them. Don't
duplicate them in skill files, where they go stale.

## International-market guidance

- **Optional summary**: 2–3 sentences on what the candidate does and the value they bring. Skip
  it if it would only restate the header.
- **Career gaps need no explanation on the CV.** Don't add a line justifying one.
- **Quantification nuance:** numbers help, but never force a fake one. A genuine outcome can
  carry a bullet without a hard number, as long as it's honest.
- **Team work:** frame contributions as part of a team unless the candidate genuinely owned the
  result: "worked as [role] on X, which achieved Y".
- **Two-column layouts** are popular for saving space but some ATS parsers scramble them. Stay
  single-column unless a specific application clearly benefits.

## Process

1. **Don't keyword-stuff the body.** People read CVs; crammed keywords sound robotic. Pull the
   ad's language in where it's already true (`jd-tailoring.md`).
2. Confirm the target role first; pull the 3–5 things the posting actually weights.
3. Reorder and trim the base bullets (or pick stored variants) to foreground those. No new claims
   for keywords without evidence.
4. A real skill gap is an interview or cover-letter topic, not something to paper over on the CV.
